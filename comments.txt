Race Condition Issue: Multiple hotfixes can be skipped

The current implementation only checks for thee)
This creates a race condition when multiple hotfixes are merged in quick succession:

Scenario:

10:00 AM - Hotfix A merged to main → Workflow queued
10:01 AM - Hotfix B merged to main → Workflow queued
10:05 AM - First workflow runs, searches for latest hotfix, finds Hotfix B, cherry-picks it
10:06 AM - Second workflow runs, searches for latr cherry-picked to develop.

Recommended solution: Trigger on pull_request closed event instead of push to main. This ensures each merged PR gets its own workflow run:

on:
  pull_request:
    types: [closed]
    branches:
      - main

jobs:
  cherry-pick:
    if: |
      github.event.pull_request.merged == true &&
      startsWith(github.event.pull_request.head.ref, 'hotfix/')
This approach:

Guarantees every hotfix is processed
Eliminates race conditions
Uses actual branch name from PR metadata (works with all merge strategies)
